# PRODUCT_BASELINE｜检查单小程序 MVP V1.0 产品基线

## 1. 产品定位

面向个人及家庭成员的长期检验报告管理工具。通过拍照或相册上传纸质报告/电子报告截图，将检验数据结构化保存，通过标准指标关联不同时间、不同医院的同类指标，并提供报告查看、异常结果查看、关注指标和历史趋势。

不是：医疗诊断系统、AI 问诊、疾病风险预测、治疗或用药建议工具。

## 2. 核心用户

MVP 只有普通微信用户。

一个微信用户可管理多个健康档案：
- 本人；
- 父亲；
- 母亲；
- 配偶；
- 其他家庭成员。

V1.0 不做复杂家庭多人协同、成员邀请和共同编辑权限。

## 3. 核心产品闭环

```text
进入小程序
→ 登录
→ 创建/选择健康档案
→ 拍照/相册上传报告
→ 图片预览、排序、删除、补图
→ OCR
→ AUTO / REVIEW
→ 报告信息确认
→ REVIEW 人工处理
→ 疑似重复检查
→ 用户 commit
→ 正式检验报告
→ 报告视角 / 指标视角
→ 历史结果 / 趋势
→ 回到对应原始报告核对
```

## 6. OCR 人工确认规则

### AUTO
- 表示当前 Pipeline 达到产品允许自动采用的安全条件；
- 默认采用；
- 不要求逐行点击确认；
- 用户仍可主动编辑；
- AUTO 仍需要用户对整份报告执行最终 commit。

### REVIEW
- 必须醒目标记“待确认”；
- 可以查看原图、修改指标/结果/单位/参考范围、选择标准指标、按原名称保存、删除错误识别；
- 所有 REVIEW 必须被处理为 resolved，整份报告才允许 commit。

“处理完成”可以是：确认正确、人工校正、选择标准指标、按原名称保存、删除错误项。

## 7. 三种数据来源

正式结果至少区分：
- OCR 自动识别；
- OCR 后人工校正；
- 纯手工录入/手工新增。

报告详情可轻量提示“部分数据经人工校正”，但不干扰正常浏览。

## 8. 正式数据准入

OCR 临时结果不属于正式健康数据。

只有用户执行最终 commit 后生成的正式报告/结果，才能进入：
- 报告列表；
- 我的指标；
- 最新结果；
- 历史结果；
- 趋势。

## 9. 趋势规则

- 时间使用检验日期/时间，不使用上传日期；
- 同一天多次结果全部保留；
- 参考范围属于单次结果；
- 不兼容单位不画在同一序列；
- V1.0 不随意进行跨单位数值换算；
- 非数值结果可以保存并进入历史列表，但不强行进入普通折线图；
- 趋势中的结果必须可以追溯至对应报告和原始图片。

## 10. 原始报告规则

系统结构化结果用于管理和趋势，原始检验报告始终作为最终核对依据。

任何人工修改、标准指标映射、单位处理都不得覆盖：
- 原始图片；
- 原始 OCR 快照。

## 11. 疑似重复

综合健康档案、医院、检验日期、报告编号、指标集合判断。

发现疑似重复：
- 提示用户；
- 允许查看已有报告；
- 允许继续保存；
- 不直接禁止保存。

## 12. 健康档案隔离

每份报告、指标历史和关注状态必须属于明确健康档案。

切换档案后首页、报告、我的指标等全部切换数据上下文。不同成员数据不得混合。

正式保存前可切换所属档案；正式保存后允许整份报告迁移到其它本人管理的档案。

## 13. 首批支持范围

重点支持常见中文医学检验类表格报告：
- 血常规；
- 常规血生化；
- 肝功能；
- 肾功能；
- 血脂；
- 血糖；
- 电解质；
- 心肌酶/心肌标志物。

在真实样本回归充分后扩展：
- 肿瘤标志物；
- 甲状腺功能。

不宣传“所有医院、所有报告都支持”。

## 14. V1.0 明确不做

- 医疗诊断；
- 疾病风险预测；
- AI 问诊；
- 用药建议/药品管理/用药提醒；
- 医生咨询；
- 自动健康评分；
- 医学关联分析；
- CT/MRI/病理报告分析；
- 电子病历；
- 医院/HIS/LIS 接口直连；
- 微信医院数据自动同步；
- 复杂家庭多人协作；
- 公开分享；
- 复杂运营后台；
- 在线算法参数配置。
